大语言模型基础 ​

大语言模型（Large Language Model，LLM）是对 token 序列建立概率模型的神经网络。它可以生成文本、代码或结构化数据，也可以在多模态系统中处理图像和音频。流畅输出不等于事实正确，模型能力必须在具体任务、数据和约束下验证。

学习目标 ​

读完本页后，你应该能够：

  • 解释 token、Embedding、自注意力、上下文窗口和自回归生成。
  • 区分 encoder、decoder、encoder-decoder 以及混合架构。
  • 理解预训练、监督微调和偏好优化各自解决的问题。
  • 区分参数中的统计模式、请求上下文和外部工具提供的信息。
  • 设计一个包含评估、引用、安全和成本约束的 LLM 应用最小闭环。

LLM 实际在做什么 ​

以常见的 decoder-only 模型为例，训练目标是估计：

text
P(token_t | token_1, token_2, ..., token_(t-1))

也就是根据前文预测下一个 token 的概率分布。生成时，模型选择或采样一个 token，把它追加到上下文后继续预测，直到遇到停止条件。

“预测下一个 token”描述了训练目标，但不能完整概括模型在大规模训练后形成的表示、上下文学习和工具使用能力；同样，这些能力也不证明模型具有与人相同的理解或意识。

从文本到输出 ​

text
输入
  -> 分词器把内容编码为 token ID
  -> token Embedding 与位置信息形成初始表示
  -> 多层注意力与前馈网络更新表示
  -> 输出层产生下一个 token 的 logits
  -> 解码策略选择下一个 token
  -> 重复直到停止

Token 化 ​

Token 可以是词、子词、字符、字节或它们的组合。不同模型使用不同分词器，因此：

  • 同一段文本在不同模型中的 token 数可能不同。
  • 中文、代码、表格和特殊字符的压缩效率可能差异很大。
  • 上下文限制、费用和延迟应按目标模型的分词器实测，不能只按字数估算。

Embedding 与位置 ​

token ID 会映射为向量。模型还需要位置信息来区分相同 token 在序列中的不同位置。位置编码可以是固定编码、可学习向量、RoPE 或其他变体。

Embedding 的几何关系由训练过程形成，不是“把字典定义直接存进向量”。同一个 token 的上下文表示会在网络层中不断变化。

Transformer 与自注意力 ​

Transformer 最早由 2017 年论文《Attention Is All You Need》提出。缩放点积注意力可写为：

text
Attention(Q, K, V) = softmax(QK^T / sqrt(d_k))V
  • Query表示当前位置要寻找什么。
  • Key表示每个位置可被匹配的特征。
  • Value表示匹配后聚合的信息。
  • 多头注意力让模型在多个投影子空间中并行计算关系。

因果注意力不是双向预测 ​

GPT 类 decoder-only 模型通常使用因果掩码：位置 t 只能关注当前位置及之前的 token，不能看到未来 token。BERT 类 encoder 模型可以双向利用上下文，但通常不是用来逐 token 自回归生成。不能把“Transformer 有自注意力”直接写成“所有 LLM 都会双向预测”。

复杂度与上下文窗口 ​

标准全注意力对序列长度的计算和注意力矩阵内存开销近似按平方增长。FlashAttention 优化了内存访问和中间存储，但没有把标准全注意力的数学关系改成线性复杂度。

上下文窗口表示一次请求最多可参与计算的 token 范围，不代表模型能同等准确地利用窗口内每一个位置。长上下文仍要评估检索位置、噪声、延迟和成本。

不只有一种模型架构 ​

架构典型训练方式常见用途
Encoder-only掩码建模、对比学习分类、检索、序列标注、Embedding
Decoder-only因果语言建模文本和代码生成、对话、工具调用
Encoder-decoder条件生成翻译、摘要、输入到输出转换
MoE每个 token 只激活部分专家在增加总参数的同时控制单次计算量
状态空间或混合模型递推状态、注意力与其他序列模块组合长序列和流式处理的不同权衡

现代生成模型大量使用 Transformer，但不能说所有 LLM 都是纯 Transformer。Mamba、RWKV 以及各种注意力混合架构说明序列建模还有其他路线。

训练与后训练 ​

预训练 ​

预训练从大量 token 中学习语言、代码和数据中的统计规律。decoder-only 模型常用下一个 token 预测；encoder 模型也可能使用掩码恢复或对比目标。训练数据不是简单的“整个互联网”，通常还涉及授权、过滤、去重、配比和质量控制。

监督微调（SFT） ​

SFT 使用指令与理想回答等样本，让基础模型更好地遵循任务格式和对话规范。它可以改变行为分布，但不会保证消除预训练中的错误知识或偏见。

偏好优化 ​

  • RLHF通常包含偏好数据、奖励建模和强化学习优化。
  • DPO等直接偏好优化方法可以不单独训练奖励模型，但仍需要偏好对、参考策略或相应训练假设。
  • 可验证奖励适合数学、代码测试和形式化任务，但容易受奖励漏洞影响。

不同实验室的后训练配方并不公开且持续变化，不能把 RLHF 写成所有聊天模型唯一或固定的训练流程。

生成与解码 ​

方法作用注意事项
Greedy每次选择最高概率 token可复现，但可能重复或陷入局部选择
Temperature缩放 logits 的尖锐程度越高通常越多样，不等同于“更有创造力”
Top-k只保留概率最高的 k 个候选固定候选数量
Top-p保留累计概率达到 p 的最小候选集合候选数量随分布变化
Beam search同时保留多个序列候选常用于翻译等任务，对开放式对话未必更好

采样随机性是输出变化的一个来源，但服务端更新、并行计算和浮点非确定性也可能影响复现。要求稳定输出时，应使用结构化约束、固定版本和回归评估，而不是只把 temperature 设为 0。

模型的三类信息来源 ​

来源说明主要风险
参数训练形成的统计表示过时、近似记忆、偏见、无法逐条追溯
当前上下文系统指令、用户输入、示例和检索片段超窗、冲突指令、提示词注入、噪声
外部工具搜索、数据库、代码执行和业务 API权限、工具错误、数据新鲜度、执行副作用

LLM 本身通常不会自动查询数据库，但应用可以为它提供检索和工具。把“所有知识都压缩在权重中”作为绝对描述，会忽略系统提示、当前上下文、缓存、检索和工具结果。

RAG、微调与工具调用如何选择 ​

需求优先考虑
需要引用可更新的私有知识RAG 或受控查询工具
需要稳定输出格式和风格提示模板、结构化输出，必要时 SFT
需要调用真实系统执行动作工具调用 + 参数校验 + 权限控制
需要学习领域行为模式高质量微调数据与评估
需要修正单条最新事实更新外部数据源，不宜只靠微调

这些方法可以组合。RAG 也不能保证事实正确：检索可能漏召回、召回错误内容，生成阶段还可能错误引用或忽略证据。

如何评估 LLM ​

不要用一个排行榜分数代表全部能力。至少分层评估：

  1. 任务成功：答案、代码、工具结果是否满足业务目标。
  2. 事实与证据：关键结论是否被提供的来源支持，引用能否定位。
  3. 指令遵循：格式、长度、语言和禁止项是否满足。
  4. 安全与权限：能否抵抗提示词注入，是否越权读取或执行。
  5. 鲁棒性：改写、长上下文、噪声、边界输入和多轮对话下是否稳定。
  6. 性能与成本：首 token 延迟、总延迟、token 用量、并发和失败率。

评估集应包含正常样本、困难样本和历史线上故障。升级模型、提示词、工具描述或检索策略后都要做回归测试。

局限与安全边界 ​

  • 幻觉：生成语法正确但事实错误或无证据的内容。
  • 知识时效：参数知识有截止时间，当前信息需要外部数据源。
  • 提示词注入：不可信文档可能包含试图改变模型行为的指令。
  • 偏见与代表性不足：训练和评估数据可能遗漏人群、语言或场景。
  • 隐私：敏感数据可能通过输入、日志、检索库或训练流程泄露。
  • 自动化风险：工具参数正确不代表动作被授权；高风险操作需要确定性校验和人工确认。
  • 不可解释性：可读解释不等于模型真实内部因果过程。

常见误区 ​

  • 参数越多一定越强：数据、架构、训练配方、推理预算和任务匹配同样重要。
  • 上下文越长效果越好：长上下文会增加噪声、延迟和成本，利用率需要实测。
  • 模型说得自信就是概率高：语言风格不是经过校准的置信度。
  • 思维链越长越正确：更多推理 token 可能有帮助，也可能放大错误路径。
  • 开源模型等于开源软件：很多模型只是开放权重，许可证可能限制用途、规模或再分发。
  • 量化几乎无损：损失取决于模型、位宽、量化方法、硬件和目标任务。
  • 只改提示词即可上线：生产系统还需要评估、权限、可观测性、降级和人工兜底。

学习路径 ​

  1. 用小模型观察 token 化和采样参数对输出的影响。
  2. 理解因果掩码、自注意力、残差连接和归一化。
  3. 学习预训练、SFT、偏好优化与评估的区别。
  4. 构建一个带引用的最小 RAG，再分析检索和生成各自的错误。
  5. 增加一个只读工具调用，验证参数、超时和权限失败路径。
  6. 建立固定评估集后再比较模型，而不是先看排行榜选型。
