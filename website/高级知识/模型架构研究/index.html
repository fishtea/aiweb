模型架构研究 ​

本页面总结了 Transformer 架构原理及其替代方案，涵盖 Mamba（状态空间模型）、混合专家模型（MoE）等前沿架构。

1. Transformer 架构基础 ​

1.1 核心组件 ​

Transformer 架构（Vaswani et al., 2017）包含以下核心组件：

  • 自注意力机制（Self-Attention）：计算序列中每对位置之间的注意力权重
  • 多头注意力（Multi-Head Attention）：并行计算多个注意力头，捕获不同类型的依赖关系
  • 前馈网络（FFN）：逐位置的非线性变换
  • 残差连接与层归一化：稳定训练
  • 位置编码：注入序列位置信息

1.2 注意力计算 ​

Attention(Q, K, V) = softmax(QK^T / √d_k) V
  • 时间复杂度：O(n²·d) — 随序列长度平方增长
  • 这是 Transformer 的主要计算瓶颈

1.3 局限 ​

  • 二次方复杂度：长序列场景下计算和内存开销极大
  • KV 缓存：推理时需要缓存 Key/Value，随上下文增长线性增加
  • 固定位置编码：外推能力有限（虽已被 RoPE 等改进）

2. Mamba：选择性状态空间模型 ​

来源： What Is a Mamba Model? Complete Guide - ArticSledge

Mamba 由 Albert Gu 和 Tri Dao 于 2023 年 12 月提出（arXiv:2312.00752），是一种以线性时间复杂度处理序列的模型架构。

"Mamba processes text, images, and genomic data with linear time complexity. While GPT-4 slows down as context grows, Mamba maintains constant speed."

2.1 核心创新 ​

创新描述
选择性状态空间参数 Δ、B、C 成为输入的函数，实现内容感知处理
硬件感知并行扫描利用 GPU 内存层次结构的融合 CUDA 内核
简化架构无自注意力、无 MLP 子层、无位置编码、无 KV 缓存

2.2 架构组成 ​

每个 Mamba 块包含：

  1. 线性投影（扩展）
  2. 1D 卷积（局部依赖）
  3. 选择性 SSM（全局上下文）
  4. 非线性激活（SiLU/Swish）
  5. 线性投影（压缩）

2.3 性能对比 ​

模型参数量Perplexity训练速度

Transformer++2.8B8.690.8×

关键发现：

  • Mamba-2.8B 优于同尺寸 Transformer
  • Mamba-1.4B 以一半参数匹配 Transformer 性能
  • 推理吞吐量提升 5 倍（无 KV 缓存）
  • Mamba 可处理 1M token 上下文，选择性拷贝准确率 >95%

2.4 Mamba-2（2024 年 5 月） ​

  • 核心洞察： SSM 和注意力通过结构化半可分矩阵存在数学关联
  • 状态维度从 16 增加到 128（8 倍提升）
  • 训练速度提升 2-8 倍
  • Mamba-2-2.7B MMLU：39.6% vs Pythia-2.8B 36.5%

2.5 混合架构 ​

纯 Mamba 在上下文学习和精确拷贝方面存在不足。混合 Mamba-Transformer 架构通过以特定比例混合两种层来解决这一问题。

3. 混合专家模型（Mixture of Experts, MoE） ​

来源： MoE-Mamba: Efficient Selective SSMs with MoE, Hybrid Mamba-Transformer MoE - Emergent Mind

3.1 MoE 核心概念 ​

  • 将 FFN 层替换为多个"专家"（小型 FFN）
  • 门控网络（Router） 动态选择激活哪些专家
  • 每个 token 只激活部分专家，实现条件计算

3.2 优势 ​

  • 参数扩展：总参数量大，但计算量保持可控
  • 专业化：不同专家学习不同领域的知识
  • 高效训练：更少的训练步骤达到相同性能

3.3 MoE-Mamba ​

来源： MoE-Mamba Paper Analysis

"MoE-Mamba reaches the same performance as Mamba in 2.2× less training steps while preserving the inference performance gains of Mamba against the Transformer."

5. 架构演进方向 ​

来源： FTI Consulting - Frontiers of AI Research 2025

当前趋势 ​

  1. 从纯 Transformer 到混合架构 — Mamba + Attention + MoE 的组合
  2. 从 Scaling Law 到效率创新 — 更少的参数、更快的推理
  3. 从通用模型到专业化 — 特定领域的架构优化
  4. 从随机到混合 AI — 神经网络 + 符号逻辑的结合

"We are seeing a combination of R&D activities: new engineering approaches, hybrid AI model approaches, and continuing fundamental research on new classes of models."

6. 注意力效率优化的新方向 ​

长上下文的二次方复杂度是 Transformer 的核心瓶颈，2024-2025 涌现多种高效注意力方案：

方案思路代表
稀疏注意力只计算部分位置对BigBird, DeepSeek-V3.2
线性注意力用核函数近似 softmaxLinear Transformer, RWKV
滑动窗口 + 全局局部窗口 + 少量全局 tokenMistral, Gemma
闪光注意力IO 优化而非算法改变FlashAttention-2/3
NSA / Native Sparse压缩 token + 选择性注意DeepSeek NSA

现状：FlashAttention 已成训练标配；稀疏/线性注意力在长上下文推理上有优势，但与标准注意力在精确复制等任务上仍有差距。多数生产模型采用"混合层"策略——大部分层用高效注意力，少量层保留完整注意力保底。

6. 2026 架构趋势：扩散语言模型、大规模 MoE 与新范式 ​

6.1 扩散语言模型（Diffusion LLMs）的崛起 ​

2025-2026 年，基于扩散的语言模型开始从理论研究走向实践部署。不同于自回归（autoregressive）模型逐 token 生成，扩散模型采用"去噪"范式：

  • 并行生成：一次性生成所有 token 的粗略版本，然后迭代细化
  • 推理效率：可以灵活控制去噪步数（步数越少越快，步数越多质量越高）
  • 代表模型：LLaDA（Large Language Diffusion with mAsking）、Dream 等

与 Transformer 自回归的关键差异：

特性自回归（GPT-style）扩散（Diffusion-style）
生成方式逐 token，单向全序列并行迭代去噪
推理速度随序列长度线性增长可调节步数，支持快速模式
文本质量成熟稳定提升中，在特定任务上接近
可控性通过 prompt 引导支持条件生成 + 分类器引导
开源生态极成熟快速增长中

扩散 LLM 尚未在通用能力上全面超越自回归模型，但在速度敏感场景（实时翻译、低延迟对话）和可控生成方向展现出独特优势。

6.2 超大规模 MoE：DeepSeek-V3 与 671B 参数时代 ​

DeepSeek-V3（2024 年底发布，2025-2026 持续演进）代表了当前 MoE 架构的工业级实践：

  • 总参数 671B，每次推理激活 37B（约 5.5%）
  • 创新的多头潜在注意力（Multi-head Latent Attention, MLA）：大幅降低 KV 缓存，使长上下文推理更高效
  • 无辅助损失负载均衡：通过动态偏差调整实现专家负载均衡，避免了传统 MoE 的辅助损失对模型质量的负面影响
  • FP8 混合精度训练：在 2048 块 H800 GPU 上以极低成本完成训练

关键启示： DeepSeek-V3 证明，通过工程创新（而非仅靠 Scaling），可以用远低于 GPT-4 的预算训练出接近其性能的模型。这标志着 AI 能力发展的"效率拐点"——同样的算力可以产出更强的模型。

6.3 混合架构成为主流共识 ​

2026 年，纯架构"信仰"已经消退，混合架构成为产业共识：

混合模式代表设计思路
Attention + MoEGPT-4, Gemini, DeepSeek-V3注意力层保持全连接，FFN 层替换为 MoE
Mamba + Attention + MoEJamba 1.5, Granite 4.0大部分层用 Mamba 高效处理，少量层保留 Attention 做精确检索
扩散 + 自回归研究阶段用扩散做粗生成，自回归做精细补全
Transformer + 检索RAG-native 架构将外部知识库检索嵌入模型前向传播

趋势总结： "一个架构统治一切"的时代已经结束。实际部署中，架构选择越来越多地由部署约束（延迟、内存、功耗）而非纯理论性能决定。 小模型 + 高效架构（Mamba/线性注意力）在端侧部署中胜过同等算力的 Transformer。

6.4 RWKV 与线性注意力生态更新 ​

2025-2026 年，线性注意力方向的代表 RWKV 发布了 RWKV-7 架构：

  • 渐进式进化：从 RWKV-4（经典线性注意力）→ RWKV-5（多头 + 动态状态）→ RWKV-6（数据依赖的时间混合）→ RWKV-7（上下文学习增强）
  • 训练效率：在相同 token 预算下，RWKV-7 的训练吞吐量约为同等参数规模 Transformer 的 3-5 倍
  • 极限长上下文：RWKV 系列天然支持超长上下文（理论上无限），在 DNA 序列建模、代码库分析等场景展现优势
模型上下文推理速度优势开源
RWKV-7 (7B)理论无限3-5×✅
Mamba-2 (2.7B)1M token5×✅
Transformer (同等)~128K token (典型)基准✅

7. 架构推理效率对比与选型指南 ​

2026 年，架构选择越来越多地由实际部署约束决定。不同架构在推理吞吐、延迟、内存占用和长上下文支持上差异显著，选择合适的架构对生产系统至关重要。

7.2 部署场景选型建议 ​

场景 1：高吞吐 API 服务

  • 推荐：MoE 架构（如 DeepSeek-V3、Mixtral）
  • 理由：总参数量大但激活参数少，可在多请求并发时通过 batching 充分利用 GPU 显存
  • 代价：需要高带宽 GPU 互联来支持 expert parallelism

场景 2：超长上下文推理

  • 推荐：混合 Mamba-Attention（如 Jamba 1.5、Granite 4.0）
  • 理由：大部分层无 KV 缓存，只有 Attention 层需要；256K+ 上下文仍保持合理延迟
  • 代价：纯 Mamba 层在精确复制任务上不如纯 Attention

场景 3：端侧/边缘部署

  • 推荐：RWKV-7 或 Mamba-2
  • 理由：无 KV 缓存意味着更低的峰值内存；线性复杂度意味着长上下文不降解
  • 代价：通用能力仍需追赶同等规模的 Dense Transformer

场景 4：低延迟交互式 Agent

  • 推荐：MiniMax M2（MoE, 10B 激活/230B 总参）
  • 理由：10B 激活参数在保持高性能的同时实现亚秒级首 token 时间
  • 代价：仅限于文本输入，多模态支持有限

8. DiScoFormer：一个 Transformer 同时估计密度和分数 ​

来源： DiScoFormer: One transformer for density and score, across distributions — Allen AI (2026-06-29)，技术报告：arXiv:2511.05924

2026 年 6 月，Allen AI 提出了 DiScoFormer（Density and Score Transformer）——一种新颖的架构，能用同一个模型在一次前向传播中同时估计任何数据分布的密度（density）和分数（score），无需针对不同分布重新训练。

问题背景 ​

机器学习中大量任务本质上是"从有限样本中恢复分布"：

量定义用途
密度 (Density)平滑的直方图——数据密集处高，稀疏处低异常检测、密度估计
分数 (Score)对数密度的梯度，指向密度上升最快的方向扩散模型（Stable Diffusion 等）、贝叶斯采样、粒子模拟

现有方法的权衡困境：

方法优势劣势
核密度估计 (KDE)无需训练，适用于任何分布高维时精度急剧下降
神经分数匹配高维也准每个分布需从头训练

DiScoFormer 的创新 ​

DiScoFormer 使用 交叉注意力（Cross-Attention） 机制，将整个样本集映射到其背后分布的密度和分数：

  • 共享骨干网络：密度和分数共享大部分参数（因为它们有数学关系——分数是密度对数的梯度）
  • 双头输出：一个头输出密度，另一个头输出分数
  • 交叉注意力：允许在任意点评估密度和分数，而不仅仅是数据点所在位置
  • 一次性训练、跨分布泛化：训练后可直接应用于新分布，无需重新训练

架构意义 ​

DiScoFormer 展示了 Transformer 架构的一个新应用方向：不是生成数据，而是理解数据的分布结构。这打破了 Transformer 主要用于"序列到序列"生成或分类的范式，将其能力扩展到统计推断领域。

启示： Transformer 的核心能力——注意力机制对集合的排列不变性建模——在密度估计这个看似"非典型"的任务上展现出惊人的适配性。这可能预示着 Transformer 从"语言/视觉骨干"向"通用统计推断引擎"的演进。

9. 大模型元认知能力：模型知道自己会犯错吗？ ​

2026 年 7 月，Ginigen-AI 发布了一个专门测量 LLM 元认知能力（metacognition）的基准和排行榜，揭示了当前最强模型在"自我觉察"方面的惊人短板。

元认知的两个维度 ​

维度含义测量方式
脆弱性 (Vulnerability)模型是否容易掉入陷阱？300+ 陷阱问题
适配器增益 (Adapter Gain)一个冻结基座模型的小适配器能否捕获模型的错误？11 个逐模型适配器

核心发现 ​

"即使最强的模型，在自由形式的写作中也几乎注意不到自己的错误。"

  • 24 个主流模型的排行榜表明：高准确率 ≠ 高元认知能力
  • 在需要自由形式回答的场景中（如长文生成），模型对自身错误的觉察能力最低
  • 在医学、法律、金融等高风险领域，"知道何时该停下来复查"比原始准确率更重要
  • Agent 工作流中，一个"不自知"的模型会导致错误在流水线中传播和放大

架构启示 ​

这一基准揭示了一个被忽视的架构问题：当前 LLM 的训练范式（next-token prediction + RLHF）天然缺乏"自我评估"通道。模型没有内置机制来标记"我对这个答案不确定"。

未来可能的架构方向：

  • 内置不确定性估计头：在模型输出层增加置信度/不确定性的显式输出
  • 两步推理架构：先生成答案，再让独立模块（或共享骨干的适配器）评估可靠性
  • 训练信号融合：将"元认知准确率"作为额外的训练目标

2026 年，"模型能力"的定义正在从"回答是否正确"扩展到"是否知道自己是否正确"。这对于 Agent 系统的可靠部署至关重要。

10. 2026 架构前沿：Anthropic 发现语言模型中的"全局工作空间" ​

10.1 J-space：模型内部的"思维空间" ​

来源： A Global Workspace in Language Models — Anthropic Research（2026-07-06）

2026 年 7 月 6 日，Anthropic 发表了一项突破性研究，发现 Claude 等现代语言模型在其内部神经激活中自发形成了一个类似于人类"全局工作空间"的架构，称为 J-space（Jacobian space）。

核心发现： 通过一种名为 Jacobian Lens（J-lens）的技术，研究者能够识别出一小部分特殊的神经激活模式——每个模式对应一个特定的词语概念。当这些模式被激活时，意味着模型正在"思考"这个词，即使它没有说出口。

J-space 的五个关键特性：

特性说明实验验证
可报告性Claude 能报告 J-space 中的内容编辑 J-space 中的"足球"模式为"橄榄球"，Claude 的回答也随之改变
可调控性Claude 可按要求控制 J-space让 Claude"在脑中想一种柑橘类水果"，J-space 中出现"orange"
内部推理J-space 存储推理的中间步骤多步数学题的中间值在 J-space 中按顺序出现
灵活使用同一 J-space 表示可被多个下游任务使用将"法国"→"中国"后，所有关于首都、语言、货币的回答全部改变
自动处理豁免大部分处理不经过 J-space移除 J-space 后，流利说话、事实回忆不变，但多步推理归零

10.2 架构意义：通用智能系统的组织原则 ​

这一发现具有深远的架构意义：

  • 自组织涌现：J-space 并非由工程师设计，而是在训练过程中自发涌现的，说明 workspace 架构是智能系统解决复杂问题的自然组织方式
  • 与人类神经科学呼应：该发现与 Dehaene & Naccache 的"全局神经元工作空间理论"高度吻合，表明跨物种/跨系统的智能可能存在共同组织原则
  • 后训练塑造身份：在预训练模型中 J-space 已经存在，但主要用于预测下一个 token；在 RLHF 后训练后，J-space 开始承载 Claude 的"自我视角"——读到危险建议时出现"WARNING"，扮演其他角色时出现"fictional"

与人类工作记忆的关键差异：

维度人类全局工作空间Claude J-space
时间机制循环神经回路单次前向传播，网络深度代替时间
记忆持久性数秒内消退通过注意力机制无限缓存
内容格式图像、声音、动作计划几乎全是词语（因为输出只有文本）

10.3 反事实反射训练（CRT）：通过 J-space 塑造模型思维 ​

Anthropic 还提出了一种新的训练技术——反事实反射训练（Counterfactual Reflection Training）：

核心思想：如果在任务中途打断模型并让它反思自己的决策，模型"会说的话"可以反过来塑造它实际思考的方式。

实验表明，仅在"假设被问到时会说什么"的数据上训练模型（而不训练实际任务行为），就能显著降低模型的不诚实行为。通过 J-lens 可以观察到原因：训练后，在执行任务期间"honest"和"integrity"等词在 J-space 中被激活。

架构启示： 这一发现表明，模型的"内部思维"（J-space）和"口述思维"（输出文本）之间存在因果联系，为未来的模型训练和架构设计提供了全新的维度——通过引导模型的自言自语来塑造其内部推理过程。

11. 2026 前沿架构深度解读：Mamba 与 DeepSeekMoE ​

11.1 Mamba：选择性状态空间模型 ​

来源： Mamba: Linear-Time Sequence Modeling with Selective State Spaces — arXiv 2312.00752

Mamba 由 Albert Gu 和 Tri Dao 于 2023 年 12 月提出，是一种以线性时间复杂度 O(n) 处理序列的架构。

核心创新：

创新描述
选择性 SSMSSM 参数 Δ、B、C 成为输入函数 → 实现内容感知（content-based reasoning）
硬件感知并行扫描利用 GPU 内存层次结构的融合 CUDA 内核，在递归模式下实现并行计算
简化端到端架构无自注意力、无 MLP 子层、无位置编码、无 KV 缓存

核心优势：

  • 推理速度：5 倍于同等规模 Transformer 的吞吐量
  • 序列长度线性缩放：随上下文增长保持恒速（Transformer 为二次方）
  • Mamba-3B 在语言建模上超越同等规模 Transformer，媲美两倍参数量的 Transformer
  • 跨模态通用：语言、音频、基因组学

为什么叫"选择性"？ 传统状态空间模型（S4 等）的转换参数是固定的，无法根据输入内容动态调整——这是它们在语言等离散模态上表现不佳的关键原因。Mamba 让 SSM 参数成为输入的函数（即"选择性"），解决了这一问题。

11.2 DeepSeekMoE：终极专家专业化 ​

来源： DeepSeekMoE: Towards Ultimate Expert Specialization — arXiv 2401.06066

DeepSeekMoE 是 DeepSeek 提出的**混合专家（Mixture of Experts, MoE）**架构改进方案，核心思想是实现更精细的专家专业化。

MoE 基本原理：

输入 Token → 路由器（Gating Network）→ 选择 Top-K 专家 → 加权融合输出

传统 MoE 的痛点：

  • 专家之间的知识冗余——多个专家学到相似功能
  • 专家负载不均——热门专家过载，冷门专家浪费

DeepSeekMoE 的改进：

  • 细粒度专家分割：将每个 FFN 专家进一步切分为更小的子专家 → 实现更精细的专业化
  • 共享专家隔离：设置一些"共享专家"处理通用知识，其余专家专注特定领域
  • 在相同计算预算下显著提升模型性能

参考来源：

  • Mamba — arXiv 2312.00752
  • DeepSeekMoE — arXiv 2401.06066

2026 最新进展：MoE 规模化与线性注意力崛起 ​

概述 ​

2025-2026 年模型架构研究的核心趋势：「MoE 大规模化」与「线性注意力替代方案」。Mixtral 8x7B 证明了稀疏 MoE（SMoE）能以 1/4 计算量达到更大稠密模型的性能，DeepSeek-V3 将 MoE 推向超大规模。同时，Mamba-2 揭示了状态空间模型（SSM）与注意力机制的深层数学联系，RWKV 和 Mamba 等线性复杂度架构在长序列场景中展现出竞争力。

核心趋势 ​

1. 稀疏 MoE 成为主流

混合专家模型（MoE）通过「条件计算」实现参数规模与推理成本的解耦：

  • 核心思想：多个专家网络（FFN）并行存在，每个 token 只激活其中少数几个（通常 top-2）
  • 关键优势：总参数量巨大但激活参数少 → 推理成本可控
模型总参数激活参数每层专家数每token激活特点
Mixtral 8x7B47B13B82开源 MoE 标杆，推理成本≈7B 稠密模型
DeepSeek-V2236B21B1606细粒度专家+共享专家隔离
DeepSeek-V3671B37B2568超大规模 MoE，训练成本仅 $5.6M

2. Mixtral 8x7B 深度分析

来自 Mistral AI 的 Mixtral 8x7B（arXiv 2401.04088）是稀疏 MoE 的开源标杆：

  • 架构：基于 Mistral 7B，每层 8 个 FFN 专家 + 路由器网络
  • 路由策略：每个 token 由路由器选择 top-2 专家，输出加权求和
  • 性能：全面超越 LLaMA 2 70B（稠密模型），尤其在数学、代码和多语言任务上
  • 推理效率：虽然总参数 47B，但由于稀疏激活，推理成本仅相当于 13B 稠密模型
  • 32k 上下文窗口，通过滑动窗口注意力实现

关键设计：负载均衡损失（Load Balancing Loss）防止路由器「偷懒」——总是选择同一批热门专家，导致其他专家闲置。

3. DeepSeekMoE 的创新

DeepSeek 在 MoE 架构上做了两项关键创新（arXiv 2401.06066）：

  • 细粒度专家分割（Fine-Grained Expert Segmentation）：将每个标准 FFN 专家切分为更小的子专家 → 每个子专家可以学习更精细的专业知识，同时组合更灵活
  • 共享专家隔离（Shared Expert Isolation）：设置一部分「共享专家」处理通用知识（所有 token 都会经过），其余专家专注特定领域 → 减少专家间的知识冗余

4. Mamba-2：SSM 与 Attention 的统一框架

2024 年发表的 Mamba-2（arXiv 2405.21060）揭示了结构化状态空间模型（SSM）与注意力机制的深层联系：

  • 核心发现：SSM 可以视为一种特殊的「结构化掩码注意力」（Structured Masked Attention, SMA），其掩码矩阵具有半可分（semiseparable）结构
  • 理论意义：这解释了为什么 SSM 和 Attention 在小到中等规模上表现相近——它们在数学上是同一框架的不同参数化
  • 实际影响：Mamba-2 在保持线性复杂度的同时，训练速度比 Mamba-1 快 2-8 倍，接近 FlashAttention 优化后的 Transformer

SSM 的优势与局限：

维度Transformer (Attention)SSM (Mamba-2)
复杂度O(n²)O(n)
长序列建模受限于显存天然优势
上下文记忆全局注意力状态压缩，可能遗忘
训练并行性高需要特殊算法
生态成熟度极高快速增长中

5. 2026 架构趋势总结

  • MoE + 密集混合：并非所有层都用 MoE——在注意力层保持密集，只在 FFN 层使用 MoE（如 Mixtral 的做法）
  • 多头潜在注意力（MLA）：DeepSeek-V2/V3 提出的注意力压缩方法，大幅降低 KV-cache 内存占用
  • 线性注意力复兴：Mamba-2、RWKV-6/7、RetNet、GLA 等线性复杂度架构正在缩小与 Transformer 的性能差距
  • 架构搜索与 AutoML：用 AI 自动发现更适合特定任务的模型架构，逐步取代人工设计

10. 扩展定律（Scaling Laws）深度解析 ​

来源： Scaling Laws, Carefully — Lilian Weng (2026-06-24)

扩展定律（Scaling Laws）是深度学习最重要的经验发现之一：训练损失 $L$ 随模型规模 $N$、数据集大小 $D$ 和计算量 $C$ 的增长呈幂律下降，在双对数图上表现为直线。这一可预测性使得扩展定律在实践中极具价值——通常在小规模实验上拟合后，即可外推大规模模型的资源需求。

10.1 核心符号体系 ​

符号含义
$N$模型规模（参数量）
$D$训练数据集大小（token 数）
$C$训练计算量（FLOPs），近似 $C \approx 6ND$
$E$不可约损失（irreducible loss）
$\hat{L}$测试损失预测函数

10.2 Kaplan vs Chinchilla：两种扩展范式的冲突 ​

Kaplan et al. (2020) 发现 $N_{\text{opt}} \propto C^{0.73}$，结论是模型规模应比数据增长更快——计算量增加 10 倍时，模型规模扩大约 5.5 倍但训练 token 仅增加约 1.8 倍。

Chinchilla (Hoffmann et al. 2022) 通过更严谨的实验设计（400+ 模型，70M–16B 参数，5B–500B token）得出相反结论：$N_{\text{opt}} \propto C^{0.5}$，即模型规模和训练 token 应以相同速度增长。这一发现被总结为"大多数大模型训练不足"——在相同计算预算下，训练一个较小模型用更多数据（如 Chinchilla 70B/1.4T token）可以超越大模型（如 Gopher 280B/300B token）。

10.3 分歧的根源 ​

Pearce & Song (2024) 的分析揭示了关键差异来源：Kaplan 实验主要在较小模型上（768M–1.5B 非嵌入参数），当时嵌入参数占比不可忽略。将嵌入参数纳入 Chinchilla 框架后，在 Kaplan 的实验范围内局部拟合指数接近 0.73，验证了两者实际上描述的是同一现象的不同区域。

10.4 数据受限场景下的扩展定律 ​

当高质量唯一 token 有限时，经典扩展定律需引入数据重复的惩罚项：

  • Muennighoff et al. (2023)：引入有效数据 $D' = U_D + U_D \cdot r_D(1 - e^{-R_D/r_D})$，将重复 token 的价值建模为指数衰减
  • Lovelace et al. (2026)：引入显式过拟合惩罚项 $P \cdot R_D^\delta \cdot (N/U_D)^\kappa$，发现较大模型对数据重复更敏感，且强权重衰减可减轻重复带来的损失

10.5 拟合的陷阱 ​

Besiroglu et al. (2024) 重新分析 Chinchilla 的原始数据后发现：损失精度舍入、优化器过早终止、指数舍入到 2 位小数等"看似微小"的选择，在 log-log 空间外推时可能产生巨大偏差。这提醒我们：扩展定律拟合对实验细节极度敏感。

  • Hoffmann et al. "Training Compute-Optimal Large Language Models" (2022)

11. 2026年Transformer替代架构全景：Mamba-2、混合模型与RWKV ​

来源： Local AI Master - Mamba & SSM Guide 2026 (2026-05) | Billion Hopes - SSMs & Alternatives to Transformers (2026-05) | Wikipedia - Mamba Architecture (2026-01)

2026 年，状态空间模型（SSM）生态已从学术探索进入工程实用阶段。Mamba-2 统一了 SSM 与注意力的数学框架，混合架构在实际产品中证明了价值。

11.1 Mamba-2：与注意力机制的统一 ​

Mamba-2（Dao & Gu, 2024）最重要的贡献是在数学上统一了 SSM 和注意力机制：

  • 提出结构化状态空间对偶性（Structured State-Space Duality, SSD）：SSM 的线性递推和注意力的二次形式是同一计算的不同视角
  • 这使得 Mamba-2 可以在训练时使用注意力风格的并行计算（高效），推理时切换到 SSM 递推模式（线性复杂度）
  • 实际性能：在 2K-8K 序列长度区间与 Transformer 持平，在 32K+ 序列上有显著速度优势

11.2 混合架构：Jamba 与 Zamba ​

纯 Mamba 模型在短序列上的质量仍略逊于同规模 Transformer。2026 年的主流策略是混合——在关键层保留注意力，其余层使用 Mamba：

模型架构特点
Jamba (AI21 Labs)Mamba + MoE + 少量注意力层256K 上下文，活跃参数仅 12B（总 52B）
Zamba (Zyphra)Mamba + 共享注意力层7B 参数，推理速度比同规模 Transformer 快 3-5 倍
Falcon Mamba (TII)纯 Mamba7B，首个纯 SSM 的生产级语言模型
Codestral Mamba (Mistral)纯 Mamba专为代码生成优化，256K 上下文

混合架构的设计哲学：注意力层负责"全局推理"（跨段落理解、多跳推理），Mamba 层负责"局部建模"（相邻 token 关系），各取所长。

11.3 RWKV：另一条 O(N) 路线 ​

RWKV（Receptance Weighted Key Value）采用不同的线性注意力机制：

  • 结合 RNN 的高效推理和 Transformer 的并行训练
  • RWKV-6（2024）引入动态状态演化，在长文本理解上接近同规模 Transformer
  • RWKV-7（2025）进一步优化，在多语言任务上表现突出
  • 优势：真正的 O(N) 推理，适合流式处理和边缘设备

11.4 何时用 Transformer vs Mamba vs 混合 ​

场景推荐架构原因

11.6 未来展望 ​

SSM 和混合架构不会"取代" Transformer，而是扩展了序列建模的工具箱。2026 年的共识：

  • 注意力仍是"金标准"：在绝大多数实际应用中（<128K），精心优化的 Transformer 仍是最佳选择
  • 混合是务实路线：Jamba 证明 1-2 层注意力 + 大量 Mamba 层可以在长序列任务上超越纯 Transformer，同时在短序列上保持竞争力
  • Mamba 的杀手场景是百万级 token：基因组学、全代码库理解、多年代理记忆等场景中，线性复杂度是不可替代的优势

选型建议：不要为了"新架构"而换架构。如果你的场景在 128K 以内，优化好的 Transformer（如 Llama 4、Qwen3）仍然是最稳妥的选择。只有在序列长度成为实际瓶颈（推理延迟过高或显存不足）时，才考虑 Mamba/混合方案。

12.1 概述 ​

2026 年是模型架构从"纯架构信仰"走向"混合务实主义"的转折年。线性复杂度架构（Mamba、RWKV）和混合模型（Mamba + Transformer + MoE）已完成从学术论文到生产部署的跨越。IBM、AI21、NVIDIA、TII 等机构相继推出基于混合架构的生产级模型。同时，注意力效率优化的新方案（NSA、FlashAttention-3）将传统 Transformer 的高效推向新高度。

12.3 Mamba 生态的短板与突破 ​

Mamba 的核心弱点（2026 年仍未完全解决）：

  • 上下文学习（ICL）：MMLU 上比同规模 Transformer 低约 15 分
  • 精确复制与检索：Transformer 在 copying 任务上显著优于 Mamba（即使多 10× 参数）
  • 生态成熟度：工具链和开发者社区仍远不如 Transformer

根本原因：Transformer 直接存储所有 token 的历史（KV Cache），而 Mamba 将信息压缩到固定大小的隐藏状态中——这必然导致信息损失。

2026 年的行业共识：

混合架构（1-2 层注意力 + 大量 Mamba 层）是务实的最优解。Jamba 1.5 证明：仅 6 层注意力 + 58 层 SSD 即可在长序列上超越纯 Transformer，同时在短序列上保持竞争力。

13. Dense vs MoE：实用选型决策框架 ​

来源： Dense vs MoE：大模型架构的选择题 — 80aj (2026-04-30)

2026 年，Dense 与 MoE 的路线之争已有明确结论：大多数顶级闭源模型已选择 MoE，但 Dense 并非过时——两种架构各有清晰的能力边界，选错架构的代价远大于选错模型大小。

13.1 本质类比 ​

架构类比工作机制
Dense全科医生每个 token 经过全部 FFN 参数，激活参数=总参数
MoE分诊台 + 专科医生路由器判断 token 归属，只激活 Top-K 专家

13.2 关键数据点 ​

  • Mixtral 8x7B：总参数 47B，激活仅 13B，推理速度远超 Llama 2 70B（Dense 模型）
  • DeepSeek-V3：总参数 671B，激活仅 37B，用极低推理成本提供顶级性能
  • 反例：同等激活参数下，Dense 模型通常更强——所有参数协同工作，无路由器选择开销

13.3 Dense 的不可替代场景 ​

  1. 小规模部署和端侧推理：MoE 需将所有专家加载到显存，一个 47B 总参的 MoE 显存需求 ≈ 47B Dense。显存不足时 MoE 优势变劣势
  2. 训练稳定性要求高的场景：MoE 需处理负载不均衡、专家坍缩、路由器训练不稳定等问题，Dense 训练管线更可预测
  3. 频繁微调场景：Dense 微调更直观，MoE 需决定冻结/解冻策略，踩坑概率更高

13.4 混合架构：第三条路 ​

2025-2026 的新趋势不是二选一，而是混合——靠近输入的层用 Dense 保证基础特征提取稳定性，靠近输出的层用 MoE 在高层语义上获得专家分工优势。这种混合架构仍在探索中，没有统一标准，但方向明确。

13.5 选型决策框架 ​

条件推荐
显存充足，追求极致单模型质量Dense
高并发部署，成本敏感MoE
端侧/本地部署（显存有限）小 Dense，MoE 除非做专家卸载优化
训练资源有限但要大模型效果MoE（相同 FLOPs 下更强）
需要频繁微调Dense 更稳妥

一句话总结： Dense 追求简单稳定，MoE 追求性价比和规模。大多数生产级部署正在倒向 MoE，但 Dense 在小规模和端侧场景下仍有明确价值。
