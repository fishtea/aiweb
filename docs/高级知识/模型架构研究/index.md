# 模型架构研究

模型架构研究关注模型如何表示信息、计算关系和扩展能力。阅读新架构时，应把结构创新、训练数据、目标函数、推理实现和评估结果分开，不把论文标题当成生产结论。

## 研究维度

| 维度 | 要回答的问题 |
| --- | --- |
| 表示 | 信息以什么状态保存，如何处理长依赖 |
| 计算 | 注意力、卷积、状态空间或混合结构如何计算 |
| 扩展 | 参数、上下文、数据和算力增加时是否有效 |
| 训练 | 优化目标、稳定性、数据配比和并行策略 |
| 推理 | 显存、吞吐、延迟、KV cache 和量化成本 |
| 能力 | 在独立、可复现的基准和真实任务上是否提升 |

## 常见路线

- **Transformer**：自注意力擅长建模 token 间关系，生态成熟，但长上下文和推理缓存成本需要优化。
- **MoE**：每个 token 只激活部分专家，提高参数容量与计算量的分离度；路由负载和通信是主要工程难点。
- **状态空间/线性递推模型**：通过状态更新处理序列，可能降低长序列成本；需要关注任务类型和实现成熟度。
- **混合架构**：在不同层或阶段组合注意力、递推、卷积和专家模块，收益必须通过消融实验验证。

## 阅读论文的检查表

1. 基线是否公平，训练数据和 token 预算是否相近。
2. 提升来自架构、数据、训练技巧还是更长训练。
3. 是否报告了显存、吞吐、延迟和失败案例。
4. 代码、权重和许可证是否可获得、可复现。
5. 能力是否迁移到目标任务，而不是只在单一 benchmark 上提升。

## 与工程选型的关系

生产选型应优先看任务质量、延迟、成本、部署生态和许可证。架构新颖不代表 API 更稳定，也不代表在中文、代码、工具调用或长文档任务上更好。
