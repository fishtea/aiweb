# 数据工程与合成数据

AI 系统的质量上限通常由数据质量、权限和评估设计决定。合成数据是数据工程的一种工具，不是自动产生高质量训练集的捷径。

本页强调可追溯、可审计和可删除的数据生命周期，而不是追求数据规模。

## 数据闭环

```text
来源登记 → 采集/授权 → 解析清洗 → 去重与脱敏 → 标注/合成
    → 版本与质量检查 → 训练/检索 → 反馈回流 → 过期与删除
```

## 必须记录的元数据

来源、许可证、时间、版本、语言、领域、敏感级别、处理步骤、质量分、标注者/生成器和删除策略。训练集、评估集、检索库不能无边界混用。

## 合成数据的使用

适合补充稀缺场景、生成格式样例、扩展边界和构造安全测试；不应替代真实分布。检查重复、偏差、模式坍塌、事实错误、隐私泄露和模型自我污染，并保留生成 Prompt、模型和筛选规则。

## 质量评估

- 覆盖：任务、语言、长度、难度和风险分布。
- 正确：标签、答案、引用和程序执行结果。
- 多样：重复率、模板化和近邻污染。
- 安全：个人信息、版权、越权和有害样例。
- 可追溯：数据版本、变更原因和回滚路径。

## 与应用的关系

RAG 需要文档版本、权限和索引更新；微调需要训练/验证/测试隔离；Agent 需要工具轨迹和失败样例；评估需要稳定、可复现的数据集。
