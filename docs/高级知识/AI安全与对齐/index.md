# AI 安全与对齐

AI 安全不是给模型加一个“拒答提示词”，而是让模型、工具、数据和发布流程在可接受的风险边界内运行。本页只保留稳定的概念框架；具体法规、模型行为和工具版本应以官方资料和当前评估结果为准。

## 适合读者

- 已掌握机器学习、LLM 应用和基本评估方法的开发者
- 负责 Agent 权限、数据安全、红队测试或上线门禁的工程师

## 安全问题分层

| 层级 | 典型问题 | 主要控制 |
| --- | --- | --- |
| 模型行为 | 幻觉、偏见、有害输出、越狱 | 数据治理、后训练、拒答与安全评估 |
| 上下文与检索 | 提示注入、恶意文档、数据外泄 | 来源隔离、引用校验、输入输出过滤 |
| 工具与 Agent | 越权、错误操作、无限循环 | 最小权限、审批、沙箱、预算和幂等 |
| 系统与供应链 | 密钥泄露、依赖漏洞、日志泄露 | 密钥管理、依赖扫描、脱敏、审计 |
| 治理与发布 | 不可解释、不可追责、版本漂移 | 风险分级、评估门禁、变更记录和回滚 |

## 对齐方法的基本脉络

- **监督微调（SFT）**：用高质量示例教模型遵循任务格式和行为边界。
- **偏好优化**：用人类或 AI 反馈优化答案偏好，常见方法包括 RLHF、DPO 等。
- **规则与宪法约束**：将安全原则显式化，再用自评、拒答和偏好数据训练或推理时约束。
- **可扩展监督与红队**：用分层评估、对抗样例和人工复核发现训练数据没有覆盖的失败模式。

这些方法不能互相替代。模型对齐解决的是行为倾向，应用安全还必须控制工具权限、数据边界和系统运行环境。

## Agent 安全基线

1. 对读写工具、外部网络、代码执行和发布动作分别授权。
2. 将外部文档、网页和工具返回值视为不可信数据，不能覆盖系统规则。
3. 高风险动作必须暂停等待人工确认，并记录审批人、参数和结果。
4. 设置最大步数、时间、Token、费用和并发预算，检测循环与异常重试。
5. 记录 `trace_id`、模型/提示词/工具版本、检索来源、决策和最终副作用。
6. 使用脱敏、租户隔离、数据保留期限和删除机制处理个人或机密数据。

## 安全评估闭环

```text
风险建模 → 建立攻击与正常样例 → 离线评估 → 红队测试
    → 灰度上线 → 追踪与人工复核 → 失败样例进入回归集
```

至少覆盖：有害内容、提示注入、越权工具调用、敏感信息泄露、引用忠实度、错误恢复和拒答质量。评估报告应记录测试集版本、模型版本、阈值、失败样例和剩余风险，不能只给一个总分。

## 常见误区

- 把“模型拒答”当成完整安全方案，忽略工具和数据权限。
- 只用静态安全分类器，不测试真实 Agent 的多步操作。
- 只做上线前红队，线上失败不进入回归测试。
- 用未经核验的新闻、营销文章或排行榜断言模型安全能力。
- 保存完整敏感对话到日志，却没有访问控制和保留期限。
