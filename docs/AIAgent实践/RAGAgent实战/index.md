# RAG Agent 实战

RAG Agent 让 Agent 在需要时检索受控知识源，再基于证据回答或调用后续工具。本页只讲“检索如何进入 Agent 闭环”；文档解析、分块和向量索引原理见 [RAG 检索增强](/进阶学习/RAG检索增强/)。

## 适合场景

企业知识库、产品文档、技术支持、法规查询和需要引用证据的研究任务。

## 运行流程

```text
用户问题 → 判断是否需要检索 → 查询改写/过滤权限
    → 混合召回 → 重排与去重 → 注入带来源的上下文
    → 生成回答/继续调用工具 → 引用与事实检查
```

## 检索工具契约

检索工具至少接收 `query`、`top_k`、租户/权限范围和时间过滤条件，返回文档 ID、片段、来源、版本、更新时间和相关性分数。不要只返回一段没有出处的文本。

## 质量控制

- **召回评估**：Recall@K、命中率和权限过滤正确率。
- **生成评估**：答案忠实度、引用覆盖率、相关性和拒答质量。
- **在线指标**：用户追问率、人工纠正率、延迟、Token 和检索成本。
- **失败归因**：查询理解、召回、重排、上下文组织、模型生成或权限层。

## Agent 特有的风险

1. 恶意文档中的指令不能覆盖系统提示和工具权限。
2. 检索结果必须按用户身份过滤，不能先召回再让模型“自觉隐藏”。
3. 低置信度或无证据时应明确说明未知，并请求补充信息。
4. 写操作不能因为文档中的建议而自动执行，必须经过工具权限和审批。

## 最小验收集

准备包含同义问法、跨文档问题、过期版本、无权限文档、恶意指令和答案不存在问题的真实样例；逐条检查引用是否支持结论，而不是只看语言是否流畅。
