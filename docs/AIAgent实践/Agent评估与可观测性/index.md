# Agent 评估与可观测性

Agent 的结果取决于模型、Prompt、工具、检索、状态和执行环境。只看最终答案无法解释失败，因此必须同时记录运行轨迹和结果。

## 必须记录的事件

`trace_id`、`task_id`、模型/Prompt/工具版本、输入摘要、计划、工具名与参数、权限/审批、检索文档 ID、结果摘要、耗时、Token、错误、重试和最终验收。

敏感内容应脱敏、分级访问并设置保留期限；日志不是无边界的聊天备份。

## 指标分层

| 层 | 指标 |
| --- | --- |
| 结果 | 任务完成率、正确性、忠实度、引用覆盖率 |
| 过程 | 工具选择/参数准确率、步数、循环、重试恢复率 |
| 资源 | Token、费用、首 token、端到端延迟、并发 |
| 安全 | 注入、越权、泄露、副作用和人工接管 |
| 稳定性 | 超时、限流、失败分类、版本回归和漂移 |

## 评估闭环

```text
线上 trace → 人工标注失败 → 形成回归集 → 离线对照
    → 质量/成本/安全门禁 → 灰度 → 持续监控
```

先按失败归因，再决定改 Prompt、检索、工具 schema、模型、状态或权限。不要用换模型掩盖系统设计问题。

## Agent 专属测试

- 任务是否在预算内结束，而不是无限循环。
- 工具失败后是否重试、降级或请求人工。
- 多 Agent 交接是否保留来源和未决问题。
- 长任务暂停后是否从 checkpoint 恢复且不重复副作用。
- 高风险动作是否在审批前停止。

## 最小质量门禁

每次变更至少通过固定真实样例、边界/恶意样例、工具失败样例和成本延迟对照；高风险场景增加人工抽查和回滚演练。
