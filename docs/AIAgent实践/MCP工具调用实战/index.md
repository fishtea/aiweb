# MCP 工具调用实战

> 本文介绍如何把 Model Context Protocol（MCP）接入 Agent 应用，重点覆盖工具发现、权限控制、错误处理和可观测性。示例以通用 MCP 客户端为主，具体 SDK API 请以对应项目的当前文档为准。

## 适合读者

- 已了解 LLM、函数调用和 Agent Loop 的开发者
- 正在把内部 API、数据库或文件系统接入 Agent 的团队
- 需要统一工具协议、降低连接器维护成本的工程师

## MCP 解决什么问题

传统 Agent 集成通常为每个工具单独编写 schema、鉴权、传输和错误适配。MCP 将这些能力抽象为标准化的客户端—服务器协议，使 Agent 可以在运行时发现工具、读取资源并调用提示模板。

MCP 不等于“让模型直接执行任意代码”。模型只负责提出结构化调用意图，客户端仍需要执行权限校验、参数验证、超时控制和审计记录。

## 核心概念

| 概念 | 作用 |
|------|------|
| Host | 承载 Agent 体验的应用，例如 IDE、桌面助手或 Web 服务 |
| Client | Host 内部的协议客户端，维护与 Server 的会话 |
| Server | 暴露工具、资源和提示模板的服务进程 |
| Tool | 可被调用的动作，通常包含名称、描述和 JSON Schema |
| Resource | 可读取的上下文资源，例如文档、数据库记录或文件 |

## 一次调用的生命周期

```text
建立会话 → 协商能力 → 列出工具 → 模型选择工具
  → 客户端校验参数与权限 → 调用 Server
  → 返回结构化结果 → 模型生成答复 → 记录审计轨迹
```

建议将“模型决策”和“工具执行”分层：模型输出不应直接穿透到数据库写入、付款、删除或发送消息等高风险操作。

## 最小落地步骤

### 1. 设计工具边界

每个工具只完成一个清晰动作，输入 schema 应尽量严格。描述中写明适用场景、必填字段、幂等性和失败条件，避免把一个工具包装成万能函数。

### 2. 建立客户端策略

- 为每个 Server 配置独立身份和最小权限
- 设置连接、读取和执行超时
- 对工具列表和 schema 做缓存，但要支持版本失效
- 为调用设置请求 ID，串联模型响应、工具日志和业务日志

### 3. 执行前做确定性校验

```python
def execute_tool(call, registry, user):
    tool = registry.get(call.name)
    if tool is None:
        raise ValueError("unknown tool")
    validate_json_schema(call.arguments, tool.input_schema)
    authorize(user, tool.required_scopes, call.arguments)
    return tool.invoke(call.arguments, timeout=10)
```

示例中的 `authorize` 和 `validate_json_schema` 必须由应用实现，不能仅依赖模型遵守提示词。

### 4. 处理结果与失败

工具返回值应区分成功、可重试失败、业务拒绝和权限错误。对网络抖动可使用有限次数的指数退避；对删除、写入等非幂等动作，不应无条件重试。

## 安全与治理清单

| 风险 | 防护措施 |
|------|----------|
| 工具投毒 | 固定可信 Server，审核描述和 schema 变更 |
| 越权调用 | 用户、租户、工具和资源四层权限校验 |
| 提示词注入 | 将外部文本视为不可信数据，不允许其覆盖系统策略 |
| 数据泄露 | 脱敏、最小字段返回、限制跨租户查询 |
| 破坏性操作 | 二次确认、审批流、幂等键和回滚机制 |
| 供应链风险 | 锁定版本、记录哈希、扫描依赖和容器镜像 |

## 评估与可观测性

上线前至少准备三类测试：工具选择准确率、参数有效率、执行成功率。生产环境记录工具名、参数摘要、耗时、重试次数、结果状态和错误类型；敏感参数应脱敏，原始内容按保留策略存储。

不要只看“模型是否调用了工具”。更重要的是任务是否完成、是否发生越权、是否因错误重试造成重复写入，以及用户能否理解失败原因。

## 常见误区

1. 把 MCP 当作安全边界：协议只负责交互，权限边界仍在应用层。
2. 让工具描述过于宽泛：会增加错误调用和提示词注入风险。
3. 只测试正常路径：超时、空结果、部分失败和版本不兼容必须覆盖。
4. 直接把完整工具返回塞回上下文：应先裁剪、分页或摘要，避免上下文膨胀。
