## 一、这套教程解决什么问题

《Hello-Agents》把 Agent 的学习从「零散地读文章」升级为「系统性地构建」。它的核心判断是：

1. **LLM 是「技术海啸」**：大语言模型不仅改变了人机交互方式，更被视作通往通用人工智能（AGI）的曙光。
2. **Agent 是「行动者」而非「问答工具」**：AI 的价值不再止于「有问必答」，而在于自主规划、调用工具、解决复杂问题。
3. **多智能体系统（MAS）是释放 LLM 潜能的关键**：多个智能体分工、协作、辩论，才能完成宏大目标。

整部教程从「第一性原理」出发，把 Agent 的设计、构建与协作拆解为一条循序渐进的学习路径。

## 二、什么是智能体

### 2.1 经典定义

> **智能体（Agent）**：任何能够通过**传感器**感知所处环境，并自主地通过**执行器**采取行动以达成特定目标的实体。

五大核心要素：

| 要素 | 含义 |
|------|------|
| **环境（Environment）** | Agent 所处的世界，可以是物理世界或数字世界 |
| **传感器（Sensors）** | 感知环境输入的通道 |
| **执行器（Actuators）** | 对环境施加行动的通道 |
| **行动（Action）** | Agent 为达成目标执行的操作 |
| **自主性（Autonomy）** | 不依赖外部指令、自主决策的能力 |

### 2.2 传统智能体的五种类型

在 LLM 出现之前，智能体已有完整的理论谱系：

| 类型 | 决策依据 | 局限 |
|------|---------|------|
| **反射智能体** | 直接依据当前感知做反应 | 无历史记忆，无法处理复杂任务 |
| **基于模型的反射智能体** | 维护环境内部模型，结合历史决策 | 无法主动规划目标 |
| **基于目标的智能体** | 面向目标选择行动序列 | 目标单一，缺乏权衡 |
| **基于效用的智能体** | 用效用函数量化「好坏」再决策 | 效用函数难以设计 |
| **学习型智能体** | 从经验中持续改进 | 依赖训练数据与反馈 |

### 2.3 LLM 驱动的新范式

LLM 智能体通过海量数据预训练获得**隐式世界模型**与**涌现能力**，能直接处理高层级、模糊的自然语言指令，而无需传统符号系统的显式建模。这是 Agent 从「专用」走向「通用」的关键转折。

### 2.4 智能体的运行机制：Agent Loop

智能体循环（Agent Loop）是 Agent 的核心运行骨架：

```
感知（Perception） → 思考（Thought） → 行动（Action） → 观察（Observation） → 回到感知
                            │
                            ├── 规划（Planning）
                            └── 工具选择（Tool Selection）
```

交互遵循 **Thought-Action-Observation 协议**：Agent 输出结构化的「思考 + 行动」，环境返回「观察」作为下一轮输入。

### 2.5 Workflow 与 Agent 的区别

| | Workflow（工作流） | Agent（智能体） |
|---|---|---|
| **执行方式** | 按部就班执行预设指令 | 赋予自由度，自主达成目标 |
| **关键能力** | 确定性、可预测 | 自主性、目标导向、动态行动 |
| **适用场景** | 步骤固定、可预见 | 路径不确定、需要灵活决策 |

> 经验法则：能用工作流解决的不要用 Agent——自主性的代价是更高的不确定性。

## 三、智能体三大经典范式

构建 LLM Agent 最核心的三种设计范式，分别对应「边想边做」「先想后做」「做完再想」三种策略。

### 3.1 ReAct（推理 + 行动）

将**推理（Reasoning）**与**行动（Acting）**显式结合，形成「思考 → 行动 → 观察」循环。

- **特点**：高可解释性、动态规划、自我纠错、工具协同。
- **局限**：强依赖 LLM 能力、执行效率偏低、提示词脆弱、可能陷入局部最优。
- **适用**：探索性、需要外部工具输入的任务。

### 3.2 Plan-and-Solve（先规划后执行）

任务处理分为「先规划（Plan）后执行（Solve）」两个阶段：先生成完整计划，再严格按计划逐步执行。

- **特点**：结构清晰、执行稳定。
- **局限**：对任务的可分解性要求高。
- **适用**：结构性强、可清晰分解的复杂任务（如逻辑路径确定的推理）。

### 3.3 Reflection（自我反思与迭代）

引入「事后自我校正循环」，形成「执行 → 反思 → 优化」三步闭环，审视工作、发现不足、迭代优化。

- **特点**：提供内部纠错回路，持续优化质量，构建临时「短期记忆」。
- **局限**：增加推理轮次与成本，对实时性不友好。
- **适用**：对结果质量、准确性和可靠性要求极高，且对实时性要求宽松的场景。

### 3.4 范式选型策略

| 范式 | 核心循环 | 一句话适用场景 |
|------|---------|--------------|
| **ReAct** | 思考 → 行动 → 观察 | 探索性强、需要外部工具 |
| **Plan-and-Solve** | 规划 → 执行 | 逻辑路径确定、内部推理密集 |
| **Reflection** | 执行 → 反思 → 优化 | 质量要求极高、可容忍多轮 |

## 五、学习建议

1. **理论与实践结合**：教程强调亲手运行、调试、修改代码，而非只读概念。
2. **循序渐进**：先跑通单体 Agent（基础篇 + 单体篇），再进入记忆、协议、评估等高级主题。
3. **举一反三**：把每个范式的最小实现读懂后，替换模型、替换工具、替换场景再复现。
4. **配合阅读**：学习路径中的「记忆与检索」「通信协议」「性能评估」三章，建议对照本站对应专题深化。
