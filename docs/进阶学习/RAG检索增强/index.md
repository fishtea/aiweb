# RAG 检索增强

RAG（Retrieval-Augmented Generation）在生成前从外部知识源检索证据，再把证据交给模型。它解决的是知识时效、私有数据和引用问题，不是自动修复所有幻觉。

## 适合场景

产品文档问答、企业知识库、法规和技术资料检索。若任务需要改变模型风格或稳定学习大量格式样例，应评估微调；若需要执行动作，应结合 Agent 和工具权限。

## 四层架构

```text
数据源 → 解析/清洗 → 分块/元数据 → Embedding 与索引
                                      ↓
问题 → 查询处理 → 召回 → 重排/过滤 → 上下文 → 生成与引用
```

### 数据层

保留文档 ID、版本、作者、权限、时间和来源。解析失败、重复文件、扫描 PDF 和表格应进入可观测的异常队列。

### 检索层

关键词检索适合精确术语，向量检索适合语义相似，混合检索和重排通常更稳。`top_k`、分块大小和重叠应通过真实数据集测量，不要照抄固定参数。

### 生成层

要求模型只依据提供的证据回答；没有证据时说明未知。返回引用、版本和必要的原文片段，方便用户复核。

## 评估指标

| 层 | 指标 |
| --- | --- |
| 召回 | Recall@K、MRR、NDCG、权限过滤准确率 |
| 生成 | 忠实度、相关性、引用覆盖率、拒答质量 |
| 系统 | 延迟、Token、缓存命中率、索引更新时延 |
| 业务 | 解决率、追问率、人工纠正率和用户满意度 |

## 实施步骤

1. 定义问题类型、权限模型和可接受错误。
2. 建立带标准答案和来源的最小评估集。
3. 先实现精确/关键词基线，再加入向量和重排。
4. 记录每次检索的查询、文档 ID、分数、版本和最终引用。
5. 按失败归因优化数据、分块、召回、重排或 Prompt。

## 常见误区

- 把所有文件直接切成固定长度，不保存结构和权限。
- 只看最终回答，不测召回和引用。
- 用模型自行判断是否有权限，绕过服务端过滤。
- 文档更新后不重建索引，却声称答案是最新的。
