# 模型微调技术

微调是在已有模型基础上用任务数据调整参数或适配器。它适合让模型稳定学习行为、格式或领域模式，但不应作为缺少数据治理、检索或评估的默认补丁。

## 先判断是否需要微调

| 问题 | 优先方案 |
| --- | --- |
| 知识经常变化 | RAG 或工具 |
| 输出格式不稳定 | 结构化 schema、Prompt，仍不足再微调 |
| 语气/风格/任务模式 | 高质量示例和监督微调 |
| 推理能力不足 | 先换模型、改数据和评估，微调未必有效 |
| 成本/延迟约束 | 小模型蒸馏、量化或路由 |

## 常见方法

- **全量微调**：调整全部参数，成本高、灾难性遗忘和部署负担更大。
- **LoRA/QLoRA**：训练低秩适配器，显存和存储成本较低。
- **PEFT**：通过少量参数适配任务，便于多任务切换。
- **蒸馏**：用强模型生成或指导数据，训练更小的模型。

## 数据闭环

```text
目标定义 → 样例收集/脱敏 → 去重与质量检查 → 训练/验证/测试
  → 基线对比 → 错误分析 → 小流量发布 → 回归与回滚
```

数据要包含正例、边界、拒答和失败样例；验证和测试集不能参与训练或反复调参。记录数据版本、模板、基础模型、超参、随机种子和许可证。

## 验收维度

任务质量、泛化、格式遵循、安全拒答、幻觉、延迟、Token/显存、训练成本和基础能力退化。微调版本必须与基础模型和 Prompt 基线对照。

## 常见误区

- 用少量重复样例把模型“记住”，却没有泛化。
- 用微调解决最新事实、权限或业务规则问题。
- 忽略训练数据版权、隐私和许可。
- 只报告训练 loss，不报告真实任务和回归结果。
