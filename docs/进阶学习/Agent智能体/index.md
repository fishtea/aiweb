# Agent 智能体

Agent 是一个在目标、上下文、工具和环境约束下循环执行任务的系统。它不等于“更长的 Prompt”，也不等于“无限自主”；可靠 Agent 的核心是边界清晰、状态可恢复、动作可审计。

## 适合读者

已经掌握 LLM 基础，准备构建工具调用、知识库问答、自动化流程或多步骤研究系统的开发者。

## Agent 的最小闭环

```text
目标与约束 → 规划/选择工具 → 执行动作 → 观察结果
       ↑                         │
       └─────── 验证、重试或结束 ┘
```

每一轮都应有明确的终止条件、最大步数、预算和失败策略。固定步骤优先使用 Workflow；只有路径不确定且需要决策时才引入 Agent。

## 四个核心部件

| 部件 | 责任 | 设计要点 |
| --- | --- | --- |
| 目标与策略 | 把用户请求转成可执行任务 | 明确成功标准、不可做的事和优先级 |
| 工具 | 访问外部数据或产生副作用 | 类型化 schema、最小权限、幂等和审批 |
| 状态与记忆 | 跨步骤保存事实和进度 | checkpoint、来源、作用域、过期和删除 |
| 评估与观测 | 判断是否完成、哪里失败 | trace、工具轨迹、质量、成本和安全指标 |

## 常见编排模式

- **函数调用**：模型选择一个结构化工具，适合窄任务和 API 集成。
- **ReAct**：观察与行动交替，适合需要探索的任务。
- **Plan-and-execute**：先生成计划再执行，适合可拆解的长任务。
- **多 Agent**：按角色分工，但必须定义交接协议、共享状态和冲突处理。
- **人机协作**：高风险动作暂停等待审批，不让模型自行越过权限边界。

## 运行时选型

| 入口 | 适合场景 | 状态责任 |
| --- | --- | --- |
| 托管 Agent 运行时 | 希望平台保存长任务进度 | 平台托管会话和执行基础设施 |
| Agent SDK | 应用内自定义循环、工具和交接 | 应用负责存储、审批和运行环境 |
| 直接模型 API | 自己控制每一步和协议 | 应用负责历史、重试、超时和恢复 |
| 确定性工作流 | 步骤固定、可预测 | Git、队列和 CI 状态 |

## 最小生产基线

1. 给任务设置最大步数、时间、Token、费用和并发上限。
2. 将外部输入和工具返回值视为不可信数据，防止提示注入覆盖系统规则。
3. 写操作、发布、删除、支付和权限变更必须经过权限检查和人工确认。
4. 保存任务状态、工具参数、结果引用、错误、重试和最终验收。
5. 用真实样例评估任务完成率、工具准确率、恢复率、延迟、成本和安全事件。

## 常见误区

- 任务本来是固定流程，却用 Agent 增加不确定性。
- 只有最终答案，没有中间状态和可重放证据。
- 把向量库当成万能记忆，不区分事实、事件、偏好和临时上下文。
- 给 Agent 过大的工具权限，却没有审批、预算和回滚。
