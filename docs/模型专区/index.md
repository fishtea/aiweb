# 模型专区

这里是模型选型参考，不是固定排行榜。模型名称、版本、价格、上下文、工具能力和区域可用性变化很快；生产决策必须回到厂商官方模型列表、价格页和自己的评估集。

## 先按约束筛选

| 约束 | 需要测量 |
| --- | --- |
| 任务质量 | 领域正确率、引用忠实度、工具调用和拒答 |
| 成本 | 输入/输出价格、缓存、批处理、本地显存 |
| 延迟 | 首 token、完整响应、并发吞吐和超时 |
| 部署 | API、私有云、本地、推理引擎和运维能力 |
| 风险 | 数据隐私、许可证、供应商锁定、区域可用性 |

## 推荐评估流程

1. 用真实、脱敏的任务样例建立基线。
2. 对候选模型固定 Prompt、工具、检索和输出 schema。
3. 分别记录质量、成本、延迟、失败类型和安全事件。
4. 用小流量灰度验证线上分布，再决定默认模型和降级模型。
5. 保存模型 ID、获取日期、配置和评估结果，避免“默认别名”漂移。

## 不要只看排行榜

排行榜通常无法覆盖你的语言、领域、上下文、工具和权限约束。任何“最强”“最低成本”“支持超长上下文”的结论，都必须注明来源、日期和测试条件。
