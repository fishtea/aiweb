# 开源模型部署选型

开源模型部署不是单纯比较参数量，而是在质量、显存、吞吐、延迟、许可证、数据边界和运维成本之间做取舍。

## 选型维度

| 维度 | 检查项 |
| --- | --- |
| 模型 | 任务能力、语言、上下文、工具调用和量化质量 |
| 硬件 | 权重显存、KV cache、批处理、带宽和副本数 |
| 推理 | 首 token、吞吐、并发、流式和故障恢复 |
| 软件 | Transformers、vLLM、Ollama 等支持，监控和升级路径 |
| 许可 | 商用限制、衍生模型、数据和地区要求 |
| 数据 | 是否需要离线运行、脱敏、租户隔离和审计 |

## 决策流程

1. 固定真实评估集和最低质量门槛。
2. 计算模型权重、KV cache、激活和系统余量的显存预算。
3. 用目标并发测试 Prefill、Decode、首 token 和 P95 延迟。
4. 比较量化前后质量、安全和长上下文退化。
5. 评估升级、回滚、日志、限流、健康检查和成本。

## 部署层次

- **本地实验**：Ollama 或 Transformers，优先验证任务和数据。
- **服务化推理**：vLLM 等引擎，关注连续批处理、限流、指标和滚动升级。
- **企业私有化**：增加密钥、租户、审计、模型仓库、镜像扫描和灾备。

## 验收清单

- [ ] 模型 ID、权重来源、许可证和下载日期已记录。
- [ ] 目标任务质量达到门槛，失败样例已归类。
- [ ] 显存、吞吐、P95 延迟和并发压测完成。
- [ ] 量化、长上下文和工具调用已单独测试。
- [ ] 日志脱敏、权限、回滚和升级流程已演练。
