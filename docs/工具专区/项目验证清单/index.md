# AI 项目验证清单

AI 工具和模型更新很快，项目页中的版本、价格、Star 数和性能数据都应视为带日期的快照。本清单用于在采用前完成最小核验。

## 来源优先级

1. 官方文档、发行说明、模型卡和许可证
2. 官方代码仓库与 issue
3. 可复现实验、公开基准和带方法说明的技术报告
4. 社区文章、视频和排行榜，仅作线索

## 采用前检查

| 项目 | 必查内容 |
|------|----------|
| 模型 | 官方模型 ID、上下文、模态、知识截止日期、许可证 |
| API | 价格单位、缓存计费、速率限制、区域可用性、弃用日期 |
| 推理框架 | Python/Node 版本、CUDA/ROCm/Metal 支持、量化格式、并发模型 |
| Agent 工具 | schema、权限范围、超时、幂等性、审计和人工确认 |
| 开源项目 | 最近发布、最近提交、依赖漏洞、许可证和维护者 |

## 最小验证实验

1. 固定版本，记录操作系统、硬件、依赖和配置。
2. 用 20-50 条代表性任务测试质量、延迟、吞吐和失败率。
3. 单独测试空输入、超时、限流、工具失败、越权和重复提交。
4. 记录日期、模型实际版本、token 用量和完整成本。
5. 与现有基线比较，再决定是否灰度发布。

## 文档维护要求

- 每个“最新”结论附核验日期和官方链接。
- 无法独立确认的型号、价格或性能标记为“待核验”，不放入生产命令。
- Star 数、排行榜和云价格使用“数据快照”措辞。
- 发现维护停止、许可证变化或安全公告时，立即更新选型建议。
