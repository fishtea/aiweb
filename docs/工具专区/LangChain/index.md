# LangChain

LangChain 是 LLM 应用编排生态，提供 Prompt、模型、工具、检索、Agent 和运行追踪等组件。它是工程实现选择，不替代任务边界、权限和评估设计。API 以[官方文档](https://python.langchain.com/docs/introduction/)为准。

## 适合场景

快速组合模型、工具和检索；构建可观测的链或 Agent 原型；在明确状态和错误边界后进入生产。

## 使用原则

- 先用普通函数或确定性工作流验证业务，再引入 Agent 抽象。
- Prompt、模型、工具 schema 和状态版本化。
- 工具执行必须由服务端校验权限、参数、预算和幂等。
- 记录 trace、检索来源、工具调用、耗时、Token 和错误。
- 框架升级用固定评估集对照，不只看 API 能否运行。

## 选择组件

| 需求 | 关注点 |
| --- | --- |
| 链 | 输入输出类型、重试和错误传播 |
| RAG | 文档解析、检索、权限、引用和更新 |
| Agent | 状态、循环、工具、审批和终止 |
| 编排图 | 分支、暂停、恢复、交接和可重放 |
| 追踪 | trace、反馈、评估和敏感信息处理 |

## 常见误区

- 把框架默认 Agent 当成生产安全方案。
- 为了调用一个模型引入过多抽象层。
- 只记录最终回答，不记录中间步骤和工具结果。
- 忽略版本锁定，升级后无法解释质量变化。
